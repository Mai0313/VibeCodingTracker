# Session Ledger and Remote Ledgers

## Session ledger (`src/core/src/ledger/`, `src/core/src/cache/`)

- Exists for data continuity (deleted sources keep counting), not only speed. Stores one compact JSON file per provider (`~/.vct/sessions/<provider>.json`) holding `schema_version`, whole-DB stamps (`source`), and per-session `days` keyed by local `YYYY-MM-DD` — never raw JSON, tool bodies, full `CodeAnalysis`, or prices.
- `ScanStamp` keys freshness on `files` (mtime + length of every depended-on file, including Grok sidecars, Antigravity conversation DB + `-wal`, SQLite DB + `-wal`, and Cursor tracking DB) and `parser` (`vct_core::VERSION`), plus `tiers` (tier-threshold snapshot fingerprint) for the usage half only. One file parse writes both halves (an analysis scan stamps usage with `tiers: None`, so a subsequent usage scan with thresholds re-reads once).
- Whole-DB providers (OpenCode, Hermes) re-read with `TimeRange::All` when stale and replace each returned session's half whole across all days (never merge day-by-day, or a cumulative row whose timestamp crossed midnight counts twice). Cursor stamps per store with separate `usage` and `analysis` stamps (usage reads only gauge nodes; analysis also reads tool blobs); on a tracking-DB failure, read and fold stores without writing or stamping the ledger.
- Discovery MUST run with `TimeRange::All` and apply the time-range cutoff only when folding days; otherwise a `--daily` scan mistakes older sessions for deleted ones.
- Unseen sessions are folded from the ledger as `ScanDiagnostics::retained` (keeping `all_failed` false) and marked `missing_since` unless discovery was partial (or removed if they hold no days). A reappearing source clears `missing_since`; a resumed file re-parses and moves its single day to the new mtime date. An unreadable existing database serves retained sessions without marking anything missing. `analysis --json` and `analysis FILE` stay full-parse paths outside the ledger.
- **Never delete a ledger file**: corrupt files are renamed to `<provider>.unreadable-<utc-nanos>.json`; a newer `schema_version` freezes that provider read-only; currently `SCHEMA_VERSION == 1` (any older version is also set aside until a migration exists).
- `save` checks each dirty file's on-disk stamp before overwriting and merges unseen sessions from concurrent writers (in-memory wins for shared keys). Writes are atomic; `SessionLedger::open` sweeps `.tmp*` files older than 1 hour.
- `GLOBAL_FILE_CACHE` stays a library-only compatibility API — never reconnect it to the CLI/TUI hot path.

## Remote ledgers (`src/core/src/remote/`, `src/core/src/ledger/remote.rs`)

- `[remotes].hosts` fetches computed session `days` over ssh by running `vct ledger export`, which emits one self-delimiting JSON line (`EXPORT_LINE_PREFIX`; reader takes the last matching line to ignore shell banners).
- `cwd` and `git_remote` are deliberately omitted from exports (remote URLs can contain tokens), and session keys are hashed via 128-bit FNV-1a (`export_key`) so directory paths never cross machines. **`export_key` is permanently fixed**: changing it breaks cross-machine deduplication.
- `remote::export` loads config read-only and never re-exports its own remote snapshots (prevents multi-hop chains from double-counting).
- `remote::sync` runs `ssh -o BatchMode=yes -o ConnectTimeout=10` in a new Unix session (`setsid`) so neither ssh nor an inner `ProxyJump` can grab the TUI terminal and timeouts kill the whole process group (do not join pipe reader threads after timeout — surviving descendants can hold pipes open). Hosts that are empty, start with `-`, or contain whitespace are rejected before spawning ssh. `VCT_OFFLINE` skips fetching and keeps stored snapshots.
- When `[remotes].command` is empty and the remote lacks `vct`, the probe prints `vct-missing:<os>:<arch>` and exits 127; `fetch_one` downloads and extracts the matching release archive locally, streams it gzipped over a second ssh call's stdin into `~/.local/bin/`, and `exec`s `vct ledger export` — supporting air-gapped remotes.
- Snapshot directory names (`~/.vct/remotes/<name>/sessions/<provider>.json`) sanitize every char outside `[A-Za-z0-9._@-]` and leading dots so no host escapes `remotes/`. Colliding sanitized names refuse the second host.
- `remote::prune` deletes snapshots of unconfigured hosts, and `main.rs` MUST gate it on `config::file_is_valid()` so a malformed config (which falls back to empty hosts) never wipes cached snapshots.
- Remote sessions fold via `scan::fold_remotes`, skip any `export_key` already seen locally or in an earlier remote, never enter local ledger files, and never alter `ScanDiagnostics`. One-shot CLI waits up to 30 s per host; TUI polls in background (`remote::spawn_sync_loop`, ≥ 60 s cadence, 10 min fetch cap). `analysis --json`, `analysis FILE`, and quota panels stay local.
- Unit tests in `src/core/src/remote/mod.rs` that spawn executable stand-ins MUST share `#[serial(update_spawn)]` with `src/core/src/update/` to avoid Unix `ETXTBSY` / inherited `flock` flakes.
