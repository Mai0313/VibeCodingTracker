# Providers, Parsers, and Token Accounting

## Adding a provider

Most provider fan-outs use exhaustive `match` or struct destructuring (`resolve_merged_model_breakdown`, `build_analysis_rows_with_providers`), while these literal lists and `if` ladders compile without the new provider and silently lose its numbers:

- `calculate_provider_totals_from_per_provider` (`src/core/src/usage/summary.rs`) and `calculate_analysis_provider_totals_from_per_provider` (`src/core/src/analysis/summary.rs`): hand-written `+` chains, `days_count` lines, and `accumulate_*` calls for the "All Providers" row.
- `build_provider_total_rows` (`src/tui/src/display/usage/averages.rs`) and `build_analysis_provider_rows` (`src/tui/src/display/analysis/averages.rs`): `if days_count > 0` ladders feeding the Provider Usage line, `p` panel, and static `analysis --table` summaries.
- `ALL_PROVIDERS` (`src/core/src/ledger/mod.rs`): missing a provider stops its ledger file from loading, forcing re-parses and dropping deleted sessions.
- `FILE_PROVIDERS` (`src/core/src/scan/descriptor.rs`): missing a file-backed provider skips it in ledger-backed `usage`, `analysis`, and `ledger export`.
- `visit_analysis_sessions_from_paths_with` (`src/core/src/analysis/aggregator.rs`) and `aggregate_usage_from_paths_with_providers` (`src/core/src/usage/aggregator.rs`): `if providers.<name>` ladders for non-ledger scans and `analysis --json`.
- `extension_type_from_name` (`src/core/src/analysis/aggregator.rs`): ends in `_ => None`; missing a provider leaves `analysis FILE --text` / `--table` counting the session in the total with no provider row.
- Test `PROVIDER_NAMES` (`src/tui/src/display/usage/interactive.rs`): guards provider digest tests.
- If the new provider also gains a quota panel, bump `CONFIG_VERSION` and add a row to `PANELS_ADDED_BY_VERSION` in `src/core/src/config/mod.rs` (see `references/config-update-runtime.md` and `references/quota.md`).

## Classification, `ParseMode`, and SQLite safety

- Directory walkers MUST call `parse_session_file_typed_as` (known provider), never auto-detection (`parse_session_file_typed`), to prevent metadata preambles from misclassifying a session as Codex.
- Streaming auto-detection (`classify_records`) MUST have no fixed peek window: a Claude metadata preamble (`permission-mode`, `file-history-snapshot`, …) can be arbitrarily long.
- `ParseMode::UsageOnly` skips allocating `write_file_details` / `edit_file_details` (keeping TUI RSS around ~60 MB on 200+ session directories). All scalar counters, including `total_unique_files`, MUST stay identical between `Full` and `UsageOnly` when adding fields to `CodeAnalysisRecord`.
- OpenCode, Cursor, Hermes, and Antigravity all read SQLite databases through `src/core/src/session/sqlite.rs` (cleanly closed WAL databases with header `18..20 == [2, 2]` and no `-wal` open via `file:<uri>?mode=ro&immutable=1` bracketed by pre/post fingerprints so SQLite does not create `-wal`/`-shm` sidecars; active WAL databases with `-wal` NEVER use `immutable=1` and use standard read-only open with fingerprinted private temp copy + WAL copy fallback on lock/WAL recovery). Never open a user's database read-write.

## Provider normalization and measured quirks

- **Claude Code**: One API response is written as one record per content block, repeating the whole `usage` object on every record (measured on a real corpus: 57% of assistant records are repeats, inflating tokens 2.2× and cost 2.6× if summed). `ClaudeFold::observe_assistant_usage` banks usage per `(message.id, requestId)` (`claude_request_key_parts`) with last-wins semantics — verified across 32,516 request groups with no exception (earlier streamed records carry partial `output_tokens`, never larger). Deduplication is usage-only and per-file (forked/resumed transcripts still overlap ~6%); the `tool_use` walk still visits every record. File tools count once on `tool_use` and attach details from the result without re-incrementing. `TaskCreate` / `TaskUpdate` / `TaskStop` map to `TodoWrite`; `TaskList` / `TaskOutput` stay unmapped. `advisor_message` iterations go into `CodeAnalysisRecord::advisor_usage` (`#[serde(skip)]`), intentionally outside `conversation_usage` because `analysis` credits every model in `conversation_usage` with the session's tool counts (so vct Claude `usage` runs higher than Claude Code's `/cost`).
- **Codex**: `total_token_usage.output_tokens` includes `reasoning_output_tokens`, so subtract reasoning out of output and never re-add it. `total_token_usage` is cumulative across the session: attribute each `token_count` event's delta to the active model, and treat a resumed session's pre-context replay snapshot as baseline-only. Never infer Read/Edit/Write from lexical JavaScript inside an `exec` cell (record the completed cell as one Bash call); file changes come from `patch_apply_end` (`success == true`, deduplicated against direct `apply_patch` by `call_id`).
- **Copilot CLI**: `outputTokens` includes `reasoningTokens` (verified on 1.0.x logs: 12 visible tokens reported output 353 / reasoning 341), so emit `output_tokens = output - reasoning`. Search tools (`rg`, `grep`, `glob`, `web_search`, `web_fetch`) count as Read without fabricating file paths or line counts.
- **Gemini CLI**: JSONL is an append-only event log; keep latest revision per message id and merge `$set.messages` by id. Never subtract historical metrics on `$rewindTo` (it does not refund billed usage or undo executed tools). `thoughts_tokens` is already disjoint from output.
- **Grok CLI**: `signals.json` `contextTokensUsed` is a single current context gauge (mapped to `cache_read_input_tokens`, priced via `CostSource::GrokGauge` falling back to input rate when LiteLLM cache-read is null), not cumulative billed usage. In `updates.jsonl`, `grep` exit code 2 is still a failure even when status is `completed`; `spawn_subagent` / `get_command_or_subagent_output` are ignored orchestration tools.
- **DeepSeek Harness**: Concatenated zstd frames; decode failure after some records counts as a live session's torn tail (keep records + 1 partial failure), while failure with zero decoded records is a hard error. Every assistant step reports usage on both `assistant/chunk` and `assistant/message` — hold one last-wins slot per `(turn, step)`. `outputTokens` includes `reasoningTokens`. `request/context` route is emitted on change only (carry forward). `tool/call` `arguments` is authoritative over `tool/result.meta.diffs` (diffs pad 3 context lines and omit new files); results pair via `sourceEventSeqs`. Skip `run_code` sub-dispatches. Unmapped tool names are normal, unknown event `type` is drift, and header `version != 0` is refused.
- **Antigravity**: Reads `transcript_full.jsonl`, never `transcript.jsonl` (re-encoded/truncated). Model ids come from `<root>/conversations/<id>.db` protobuf `gen_metadata` (field 1.19 model, field 1.20 `last_step_index == n - 1`). For `<config>|<backend>`, Vertex `<model>@<version>` yields `<model>`, otherwise the config name before `|`. Compaction (`CHECKPOINT`) tokens bill to the active model in `advisor_usage` (not `conversation_usage`) so they do not inherit session tool counts. Tool names are verified against the `agy` CLI only (Desktop app tool names unverified).
- **OpenCode**: Direct SQLite reader (bypasses `detector`/`parser.rs`). Already stores `output - reasoning` (pass both through without subtraction). Read metadata/messages and tool parts in one transaction. Billed via `CostSource::OpenCodeStored` (exact LiteLLM match, else stored cost in `StoredCosts::opencode`, separate from `StoredCosts::hermes` to prevent bare-model cross-contamination).
- **Cursor**: Direct SQLite reader (`store.db` protobuf DAG + `ai-code-tracking.db` model map). `analysis` decodes only fields 4, 26, and 5 (never DAG topology); `usage` is a local context-gauge approximation (SQL-filtered `0x0A` blobs) priced via `CostSource::CursorEstimate` (exact LiteLLM match else `$0`). Auto-mode `default` model intentionally prices at `$0`. There is no dashboard billing API (the old `get-filtered-usage-events` fetch was removed; raw endpoint documented in `docs/quota.md`).
- **Hermes**: Direct SQLite reader, `usage`-only, no quota panel. Reconciles `session_model_usage` against `sessions` aggregate; subtract only placeable per-model rows so unplaceable rows stay in the residual. Snap residual cost columns to `0.0` below `1e-9` (nanodollar) to avoid f64 subtraction dust emitting ghost `$0.00` active days and masking real `estimated_cost_usd` behind `actual_cost_usd`. A NULL in a per-model data column makes that row unplaceable (let residual carry it). Absent `session_model_usage` (pre-migration DB) is not drift. `last_seen`/`first_seen` are REAL epoch seconds; `output_tokens` includes `reasoning_tokens`. Billed via `CostSource::HermesStored` (`StoredCosts::hermes`).

## Cross-provider token and path invariants

- `extract_token_counts` MUST sum `thoughts_tokens` and `reasoning_output_tokens` rather than letting one overwrite the other, because cross-provider model merges can carry both keys.
- `DayEntry::add_usage_row` (`src/core/src/ledger/format.rs`) and `fold_database_sessions` (`src/core/src/usage/aggregator.rs`) MUST stay symmetric on zero-cost stored-cost entries (`cached_usage_matches_uncached_for_every_provider_source` verifies equivalence).
- `vct usage --json` normalizes every row through `usage::normalize_usage_value` (flat keys, provider-unique unpriced keys like `tool_tokens` kept, and `cache_creation` / `server_tool_use` / `above_tier` emitted only when non-zero).
- Batch diagnostics (`scan::ScanDiagnostics`): an all-failed scan with `retained == 0` returns an error; partial failures emit one stderr summary; `retained > 0` prevents an all-failed error when sources were deleted and prints one stderr note. Interactive data tabs stay best-effort (keep last-known-good payload, log details to file).
- Multi-root file discovery (`collect_provider_files_diagnostics` / `collect_provider_candidates_diagnostics`) deduplicates by `session_key` across roots only (never within a root). Codex keys on bare file name so archiving from `sessions/YYYY/MM/DD/` to `archived_sessions/` deduplicates; every other file provider keys on root-relative path.
- Codex quota session fallback (`quota/codex_session.rs`) scans both active and archived roots with separate bounds: bulk archiving can overwrite old files' mtimes with today's timestamp, so `archived_sessions/` MUST be prefiltered descending by `rollout-<ISO-8601>` filename before ranking by mtime.
- `utils::cache_layout::remove_legacy_cache_files` runs after `Cli::parse()`, resolves via `resolve_paths` (never `get_cache_dir`, so it never creates `~/.vct`), swallows all errors, and also deletes orphaned `cursor_usage_events.json`.
